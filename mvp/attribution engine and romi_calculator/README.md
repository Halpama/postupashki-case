# Задачи 6 и 7

Решение по атрибуции и инкрементальному эффекту рекламы. Полный текст с правилами, экспериментом и ограничениями: [analysis/06_attribution.md](../analysis/06_attribution.md).

Это материалы именно по задачам 6–7, не executive summary всего хакатона.

## Запуск за минуту

Python 3.10+, только стандартная библиотека. Установка пакетов и сетевой доступ не нужны. Команды выполняются из каталога `mvp/romi_calculator`.

```bash
python3 demo.py
python3 -m unittest discover -s tests -v
python3 attribution.py examples/synthetic_journeys.json --model last_non_direct --window-days 7 --output outputs/attribution_result.json
```

Для повторения проверки исходных продаж передайте путь к предоставленному CSV:

```bash
python3 audit_sales.py '/путь/к/base.xlsx - Данные.csv' --output outputs/real_sales_audit.json
```

CSV не копируется в репозиторий и не изменяется. Контрольная сумма источника сохранена в отчёте аудита. `requirements.txt` содержит только пояснение об отсутствии внешних зависимостей.

## Что реализовано

- `attribution.py`: шесть моделей распределения чистой выручки заказа по наблюдаемым событиям; JSON на входе и выходе.
- `incrementality.py`: планирование объёма выборки и ITT-разница конверсий с интервалом Newcombe для индивидуальной рандомизации.
- `demo.py`: полностью синтетический пример, сравнение 6 моделей × 4 окна, демонстрация неопределённого результата эксперимента.
- `audit_sales.py`: числа и неоднозначности реального CSV, без выдумывания источников.
- `tests/`: проверки денег, границ окна, повторных заказов, дублей, неизвестных источников и статистических границ.

Выходы: `outputs/real_sales_audit.json` — аудит предоставленной выгрузки; `outputs/synthetic_model_comparison.csv` — сравнение моделей; `outputs/synthetic_allocations.csv` — доли заказов; `outputs/synthetic_experiment.json` — учебный эксперимент. Синтетические таблицы имеют колонку `data_origin=synthetic`.

## Контракт атрибуции

Образец входа — `examples/synthetic_journeys.json`. Поля верхнего уровня: `data_origin` (`real` или `synthetic`), `orders`, `touches`, необязательное `tracking_started_at`.

Заказ содержит `order_id`, `user_id`, `paid_at` (ISO 8601 с часовым поясом), `net_revenue` (десятичная строка в рублях). Это сумма заказа после связанных возвратов, не сумма, повторённая на каждой строке курса. Одинаковые `order_id` и одновременные заказы одного пользователя отклоняются до уточнения/объединения.

Касание содержит `touch_id`, `user_id`, `occurred_at`, `source_id`, `kind`, `event_type`, `evidence`. `placement_id` и `creative_id` рекомендуются для конкретных размещений. `kind`: `paid`, `owned`, `organic`, `direct`. `evidence`: `tracked`, `self_report`, `inferred`. Основная модель использует только `tracked` с типом `click`, `bot_start`, `source_bound_lead`; неизвестные типы событий не получают атрибуцию.

Склейка идентификаторов, классификация источника и канонизация одного взаимодействия между системами выполняются до движка. Значение `tracked` должно выставляться сборщиком по реальному подтверждению. Публичная дата поста таким подтверждением не является.

Lookback: `[paid_at − window; paid_at)`, для повторного заказа — только события после предыдущей оплаты. Вход должен содержать предшествующие заказы пользователя, даже если сам отчёт строится за короткий период. Повторные касания одного источника/размещения/креатива в течение 30 минут внутри эпизода сворачиваются к первому. Разные касания с одинаковым временем получают флаг неопределённого порядка.

По умолчанию модель `last_non_direct`, окно 30 дней, полураспад time decay 7 дней. Флаги `--model`, `--window-days`, `--half-life-days` позволяют менять настройки. Любые сравнения трактуются как разные версии расчёта: выручка разных моделей и окон не складывается.

Для возврата пересчитайте исходный заказ с его прежними `paid_at`, касаниями и конфигурацией. Не передавайте отдельный возврат как новый заказ. Деньги распределяются в копейках методом наибольших остатков; поддерживается и отрицательная корректировка чистой суммы.

## Что не утверждается

Прототип не восстанавливает неизвестные исторические источники, не подключается к Telegram и не проводит реальный эксперимент. Аудит сумм не подтверждает фактическую денежную выручку без сверки платежей. Экспериментальный калькулятор не проверяет рандомизацию, полноту наблюдения или переносимость результатов. Подробный дизайн и условия применимости находятся в основном документе.

Базовые тесты запускаются стандартной библиотекой. Для реального внедрения команда добавляет сбор событий и оплат, справочник размещений, идемпотентное хранение результатов и журнал версий/возвратов. Публикация репозитория и отправка решения не выполнялись.
